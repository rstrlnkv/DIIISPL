# DIIISPL

Свой менеджер раскладок мониторов для Windows 11: раскладка собирается **внутри программы**,
мониторы опознаются **по EDID**, профиль переключается горячей клавишей. Вместе с раскладкой
переключается HDR, а в сборках Dev — ещё и вид панели задач.

## Чем отличается от «Параметров экрана» Windows

| | Windows | DIIISPL |
|---|---|---|
| Кто помнит раскладку | внутренняя база дисплеев Windows | файл профиля в `%AppData%\DIIISPL` |
| Как опознаётся монитор | номер выхода видеокарты | EDID: производитель + модель + серийный номер |
| Смена порта HDMI/DP | монитор становится «новым», раскладка теряется | профиль продолжает работать |
| Переключение | вручную, мышью | горячая клавиша или клик в трее |
| HDR | отдельный тумблер на каждый экран, сбрасывается при смене раскладки | часть профиля, выставляется всей группе после применения |
| Вид панели задач | один на всю систему | часть профиля, свой на каждое состояние экрана (только в сборках Dev) |

Идентификатор монитора выглядит так: `GSM:LG ULTRAGEAR+:306NTGY9H903`. Именно поэтому программа
не путается там, где путается Windows: у телевизора Samsung, например, hardware ID меняется
(`SAM713F` / `SAM7140`) в зависимости от режима входа, а EDID-серийник остаётся прежним.

## Установка

Готовый пакет лежит в [выпусках](https://github.com/rstrlnkv/DIIISPL/releases). Он ставит
программу как обычное приложение: в `C:\Program Files\DIIISPL` и с записью в списке
установленных программ, откуда её и удаляют. По ходу установщик показывает лицензию,
спрашивает папку, спрашивает, создавать ли ярлык в меню «Пуск», и в конце предлагает
запустить программу сразу.

Те же ответы можно задать из командной строки:

```
msiexec /i DIIISPL-0.1.0-stable-x64.msi INSTALLFOLDER="D:\Programs\DIIISPL" INSTALLSHORTCUT=0 /qb
```

Перед установкой он закрывает работающую копию — иначе файлы окажутся занятыми и
Windows потребует перезагрузки. Профили при этом не трогаются: они лежат в
`%AppData%\DIIISPL` и переустановку с удалением переживают.

Автозапуск включается в самой программе — пункт «Запускать при входе в Windows»
в меню значка в трее.

## Окно менеджера

- **Слева** — список профилей с назначенными сочетаниями.
- **В центре** — холст: мониторы перетаскиваются мышью и прилипают краями друг к другу.
  Не входящие в профиль лежат под чертой в нижнем ряду — перетащите монитор оттуда наверх,
  чтобы добавить его в раскладку; убирает обратно переключатель «Включён» в свойствах.
  Монитор, добавленный поверх соседа, встаёт рядом сам: наложенными рабочие столы быть
  не могут. Если наложить их перетаскиванием, программа скажет об этом внизу и применять
  не станет — раздвинуть придётся самому.
- **Внизу** — свойства выбранного монитора. Показывается только применимое: у выключенного
  монитора настраивать нечего, частота нужна лишь там, где у разрешения есть выбор,
  дублирование — когда есть с чем дублировать, а HDR не показывается на выходе в дубле,
  где он невозможен.
- **Применить** записывает профиль на диск и сразу включает раскладку; **Сохранить**
  только записывает. Сами собой на диск уходят сочетание клавиш и место в списке —
  а вместе с ними и всё, что вы к этому моменту наменяли в профиле. Правки на холсте,
  в свойствах и новое имя сами не уходят: при переключении на другой профиль или
  закрытии окна программа спросит, сохранять ли их.
- Кнопка **Сочетание клавиш** — нажмите её и затем сами клавиши. Работают и одиночные
  (`F13`–`F24`, `Pause`, `ScrollLock`), и комбинации с Ctrl/Alt/Shift/Win.
- Кнопка **Панель задач** — только в сборках Dev — открывает вид панели для этого профиля;
  см. отдельный раздел ниже.
- Над списком две кнопки: **+** создаёт профиль из того, как мониторы стоят сейчас,
  **···** открывает действия над выбранным — переименовать, переставить, удалить
  (то же меню вызывает правая кнопка мыши на строке списка).
- Профиль переименовывается ещё и по `F2` или двойному щелчку, переставляется `Alt+↑`
  и `Alt+↓`; точка справа от названия отмечает раскладку, применённую сейчас.
- Крестик не закрывает программу, а прячет её: она остаётся значком в области
  уведомлений, и горячие клавиши продолжают работать. Совсем выйти — пункт
  **Выход** в меню значка.
- **О программе** — внизу списка слева и в меню значка в трее: версия, номер сборки
  и число профилей, канал обновлений с проверкой по кнопке, ссылки на выпуски
  и на исходники.

Оформление следует системной теме и акцентному цвету Windows: в тёмной теме тёмен
и заголовок окна. Шрифт — Segoe UI Variable.

## Командная строка

```
DIIISPL.exe                 открыть окно менеджера
DIIISPL.exe /tray           запустить только значком в трее (используется автозапуском)
DIIISPL.exe /apply "Имя"    применить профиль
DIIISPL.exe /save "Имя"     записать текущую раскладку в профиль; если он уже
                          есть — переснять раскладку, сохранив сочетание клавиш
                          и остальные настройки
DIIISPL.exe /list           список профилей
DIIISPL.exe /delete "Имя"   удалить профиль
DIIISPL.exe /monitors       что подключено и как опознано
DIIISPL.exe /hdr            состояние HDR на каждом выходе
DIIISPL.exe /taskbar вид [AARRGGBB] [line]      (только в сборках Dev)
                          задать вид панели задач прямо сейчас: default,
                          opaque, clear, blur, acrylic. Цвет можно короче —
                          RRGGBB, тогда он непрозрачный
DIIISPL.exe /taskbar-state ["Имя"]              (только в сборках Dev)
                          что программа видит на экранах и какой вид из этого
                          следует; с именем профиля — ещё и его настройки
DIIISPL.exe /lang cs        записать образец перевода на язык «cs»
```

## HDR при дублировании

HDR в Windows — свойство **выхода**, а не рабочего стола, и любая смена топологии его гасит.
Поэтому порядок такой: сначала раскладка, потом HDR — и обязательно **одинаковый на всех выходах
группы дублирования**: если у одного выхода HDR включён, а у другого нет, Windows уводит в SDR
всю группу. Редактор синхронизирует это автоматически.

Дальше решает Windows, и решает она отказом: выходам, объединённым в дублирование,
расширенный цвет не отдаётся вовсе — проверено на связке «монитор + телевизор» и на 60 Гц,
и на 120. Поэтому у монитора в дубле поле HDR в свойствах не показывается: чтобы включить
HDR на каждом экране, разведите их врастяжку.

Программа не делает вид, что всё получилось: после применения она перечитывает реальное
состояние и, если HDR не удержался, пишет об этом в строке состояния с причиной.

**Про API.** В Windows 11 24H2 расширенный цвет и HDR разъехались: старый флаг
`advancedColorEnabled` остаётся включённым, пока дисплей работает в широком цветовом охвате,
и по нему нельзя судить о HDR — а старый `SET_ADVANCED_COLOR_STATE` на таких сборках отвечает
успехом, но HDR не выключает. Поэтому программа работает через `GET_ADVANCED_COLOR_INFO_2`
и `SET_HDR_STATE`, а старые вызовы оставлены запасными для Windows 10 и ранних сборок 11.

Проверить текущее состояние в любой момент:

```bash
DIIISPL.exe /hdr
```

## Панель задач

> **Только в сборках Dev.** В стабильной сборке этого нет: ни экрана настроек, ни
> кода, ни библиотеки оформления — она даже не кладётся в пакет. Возможность
> опирается на чужую библиотеку, работающую **внутри проводника**, и живёт там
> дольше самой программы; пока это не отстоялось, стабильному каналу она не нужна.
> Настройки, записанные сборкой Dev, стабильная не портит: секцию `[taskbar]` она
> возвращает в файл профиля нетронутой.

Вид панели задач — часть профиля. Переключились на «Кино» — панель стала прозрачной,
вернулись на «Работа» — обычной. Причём вид задаётся не один на профиль, а свой на каждое
состояние экрана: пустой рабочий стол, открытое окно, окно во весь экран, «Пуск», поиск,
представление задач, экономия заряда.

Кнопка **Панель задач** в шапке окна открывает отдельный экран настроек. Он устроен как
«обычный вид плюс исключения»: сначала задаётся, как панель выглядит всегда, потом — для
каких случаев вид другой. Каждый случай либо «как обычно», либо со своим видом; цвет
показывается только там, где он на что-то влияет, и рядом с ним виден образец. Изменения
видны сразу, на живой панели.

Виды: как в системе, непрозрачная, прозрачная, размытие, акрил. Цвет задаётся как `AARRGGBB`
или короче — `RRGGBB`; первые две цифры — насколько он плотный. Тонкая линия у края одна
на все случаи. Пока весь раздел выключен, программа панель не трогает вовсе, а при выходе
возвращает ей системный вид.

Случаи проверяются сверху вниз, побеждает первый подходящий; если не подошёл ни один,
панель выглядит обычным видом. Считается это для каждой панели отдельно, поэтому на разных
мониторах вид может отличаться: развернули окно на левом экране — левая панель одна,
правая другая.

Настроив вид один раз, незачем повторять его в каждом профиле: внизу того же экрана —
перенос между профилями. Выберите профиль в списке, чтобы взять настройки оттуда,
или нажмите **«Применить ко всем»**, чтобы разослать свои.

### Как это устроено

Снаружи панель задач Windows 11 не поддаётся: фон рисует её собственное XAML-дерево, и старая
политика акцента (`SetWindowCompositionAttribute`) до него не достаёт. Проверено замером —
цвет полосы не меняется ни в одном режиме, при том что вызов возвращает успех, и это верно
даже если применить эффект ко всем десяти дочерним окнам панели, включая
`Windows.UI.Composition.DesktopWindowContentBridge`.

Поэтому в DIIISPL перенесён компонент **ExplorerTAP** из
[TranslucentTB](https://github.com/TranslucentTB/TranslucentTB) (© Charles Milette
и участники, GPLv3): небольшая библиотека `DIIISPL.ExplorerTAP.dll` загружается в проводник,
изнутри добирается до дерева панели и публикует COM-службу оформления, а DIIISPL дёргает её
методы. Отдельная программа при этом не нужна — процесс один.

Библиотека есть только в сборках Dev — и в программе, и в пакете. В стабильной
её нет вовсе: там нет ни экрана настроек, ни кода панели задач, ни самой
библиотеки, и в проводник ничего не загружается.

При смене профиля связь со службой и память о применённом сбрасываются: панели задач
пересоздаются, прежние окна исчезают, и всё, что о них помнили, становится ложью.

### Чем Windows 11 удивляет по дороге

Три вещи, на которых легко ошибиться и которые здесь учтены (каждая ломала работу молча,
без единой ошибки в журнале):

- **Панель нельзя искать перечислением окон.** Пока открыт «Пуск», поиск или представление
  задач, окна оболочки быстро создаются и уничтожаются, `EnumWindows` обрывается на середине,
  и панель в список не попадает вовсе — ровно в тех состояниях, ради которых всё и затевалось.
  Поэтому панели ищутся по классу напрямую, через `FindWindowEx`.
- **«Пуск» нельзя опознать по окну в фокусе.** На нынешних сборках он отдаёт фокус окну
  `SearchHost`, и по фокусу «Пуск» с поиском неразличимы. Открытый «Пуск» — это видимое окно
  `StartMenuExperienceHost` во всю ширину экрана; поиск сам по себе — окно `SearchHost`
  без «Пуска» над ним.
- **Представление задач — не `CoreWindow`.** Это окно проводника класса
  `XamlExplorerHostIslandWindow`.

Посмотреть, что программа видит прямо сейчас и какой вид из этого следует:

```bash
DIIISPL.exe /taskbar-state "Кино"
```

## Язык

Программа говорит на языке Windows; сменить его можно в окне «О программе».
Встроены английский и русский.

Другой язык добавляется файлом, без пересборки. `DIIISPL.exe /lang cs` пишет
образец в `%AppData%\DIIISPL\lang\cs.lang` — простой текст `ключ = значение`, по
строке на надпись. Строка, оставшаяся в образце английской, ещё не переведена;
переведите нужные, сохраните в UTF-8, и язык появится в списке. Чего в файле нет,
берётся из встроенного перевода, так что незаконченный файл ничего не ломает.

Файлы ищутся в двух местах: `lang` рядом с программой и `%AppData%\DIIISPL\lang`.
Второе сильнее — там не нужны права администратора.

`{0}` и `{1}` в строках — это то, что программа подставляет сама: имя монитора,
число, версия. Их надо сохранить, но можно переставить, если язык требует
другого порядка. Где нужен перенос строки, пишется `\n`.

## Файлы

- профили: `%AppData%\DIIISPL\profiles\*.layout` — обычный текст, можно править руками
- переводы: `%AppData%\DIIISPL\lang\*.lang` — тоже обычный текст, см. «Язык»
- автозапуск: `HKCU\Software\Microsoft\Windows\CurrentVersion\Run\DIIISPL`
- рядом с `DIIISPL.exe` в сборках Dev: `DIIISPL.ExplorerTAP.dll` — библиотека
  оформления панели задач. В стабильный пакет она не кладётся

В секции `[taskbar]` прочерк означает «состояние выключено», а `opaque,FF101010,0` читается
как «вид, цвет `AARRGGBB`, линия у края: 1 — есть, 0 — нет». Строка `version = 2` в начале
секции не украшение: без неё файл считается написанным старой версией, и особые случаи,
оставленные «как в системе», молча выключаются.

Пример профиля:

```ini
[profile]
name = Кино
hotkey = F17
order = 2

[taskbar]
version = 2
battery = -
taskview = -
search = -
start = -
maximized = opaque,FF101010,0
visible = -
desktop = clear,00000000,0

[display]
id = SAM:Q80A:16780800
name = Q80A
enabled = 1
x = 0
y = 0
width = 3840
height = 2160
hz = 60
rotation = 1
primary = 1
clone = -1
hdr = 1
```

## Обновления

Программа сама смотрит выпуски на GitHub — раз в сутки при запуске и по кнопке
«Проверить» на странице «О программе». Найдя новое, она говорит об этом подсказкой
у значка в трее; ставится обновление на странице «О программе», кнопкой: программа скачивает пакет,
проверяет подпись и запускает установщик, а тот закрывает работающую копию и
заменяет файлы. Профили и настройки остаются на месте.

Каналов два, переключатель на той же странице:

| Канал | Что приходит |
|---|---|
| Stable | только готовые выпуски |
| Dev | ещё и предварительные — до общего выпуска, вместе с недоделками |

**Подпись обязательна.** Скачанный пакет должен быть подписан тем же сертификатом,
что и сама программа, — отпечаток зашит в неё. Не подписанный или подписанный чужим
ключом установщик не запустится, и программа скажет об этом прямо. Сертификат
самодельный, поэтому проверяется не цепочка доверия, а совпадение с известным
отпечатком: на чужой машине корень этого сертификата не установлен, и цепочка
не доказала бы ничего.

Собрать пакет из исходников:

```
installer\build-msi.cmd          стабильный пакет
installer\build-msi.cmd dev      пакет канала Dev
```

Набор WiX скрипт подтягивает сам, ставить его в систему не нужно; из готового нужен
`DIIISPL.exe`, собранный **тем же каналом** — иначе сборка пакета откажется работать.
Пакету Dev нужна ещё и `DIIISPL.ExplorerTAP.dll`, то есть `native\build-native.cmd`.

Окна установщика оформлены своими картинками вместо стандартных из набора WiX:
полоса вверху и тёмная боковина приветствия рисуются кодом (`installer\MakeArt.cs`)
теми же цветами, что и значок программы, а шрифт окон — Segoe UI вместо Tahoma.
Знак на полосе жмётся к правому краю не для красоты: пояснение под заголовком
установщик тянет почти до него, и знак покрупнее оказывался прямо поверх текста.

### Подпись

Сборка подписывает программу, библиотеку и пакет, если рядом со скриптами лежит
`installer\sign.thumbprint` с отпечатком сертификата (или задана переменная
`DIIISPL_SIGN_THUMBPRINT`). Нет сертификата — подпись молча пропускается, сборка
идёт как обычно.

Двоичные файлы подписываются не на месте, а копиями в `installer\obj\stage`:
библиотека оформления загружена в проводник, программа может быть запущена — и
`signtool` уткнулся бы в занятый файл. Заодно сборка не правит рабочий каталог.

Метка времени ставится обязательно: без неё подпись перестанет считаться
действительной в день, когда истечёт сертификат, — даже у давно выпущенных файлов.

Самоподписанный сертификат снимает предупреждение только на тех машинах, где его
корень внесён в доверенные. Для распространения нужен сертификат удостоверяющего
центра: с июня 2023 его закрытый ключ обязан лежать в аттестованном железе или
облачной службе подписи, файлом `.pfx` такие больше не выдают.

## Как это применяется

Сначала программа смотрит, не такая ли раскладка уже стоит: сходятся ли состав, разрешения,
частоты, повороты, дублирование, основной экран и взаимные позиции. Если всё совпало —
дисплеи не трогаются вовсе. Это не оптимизация, а необходимость: каждый вызов
`SetDisplayConfig` пересогласовывает вывод, экран моргает, а на мониторе с HDR это ещё
и заметный скачок яркости. Нажать горячую клавишу профиля, который уже применён, должно
быть безобидно.

Если раскладка отличается, программа не просит Windows «вспомнить сохранённую конфигурацию».
Она сама собирает массивы путей и режимов CCD (`DISPLAYCONFIG_PATH_INFO` /
`DISPLAYCONFIG_MODE_INFO`) и отдаёт их в `SetDisplayConfig`:

1. По EDID находит текущие выходы для мониторов профиля.
2. Раздаёт группам source id: одна группа = один рабочий стол, дублирование = несколько
   выходов на одном source id.
3. Строит режимы источников с координатами, нормализует позиции так, чтобы основной монитор
   стоял в (0,0) — этого требует Windows.
4. Применяет строго — без флага, которым Windows вправе молча переписать заявку. Если
   строгая попытка отклонена, требования смягчаются по шагам (перечисление режимов, затем
   частота на усмотрение драйвера).
5. Сверяет результат с заявкой: все ли включились, в тех ли режимах, сложилось ли
   дублирование. При недостаче — повторяет и, если нужно, будит выходы штатной топологией.
6. После смены раскладки выставляет HDR.

**Про дублирование.** Выход, входящий в дубль, получает от драйвера другой `target id`:
телевизор Q80A — `16781568` вместо обычного `4352`. Пары «обычных» идентификаторов
не существует в принципе, поэтому собранная вручную конфигурация теряет второй экран,
хотя `SetDisplayConfig` рапортует успех. Программа это учитывает: если дубль ещё не собран,
его сначала строит сама Windows, а точная раскладка накладывается уже поверх — по
идентификаторам, действительным в дублировании.

## Устойчивость

Перестройка конфигурации дисплеев — тяжёлая операция в ядре графического стека. Плотная
очередь таких вызовов способна уронить видеодрайвер: при отладке этой программы серия из
примерно сорока перестроек за несколько минут привела к `0x13A KERNEL_MODE_HEAP_CORRUPTION`.
Поэтому программа держит паузу не меньше 1,2 секунды между применениями, а тяжёлое
`SDC_FORCE_MODE_ENUMERATION` идёт не первой попыткой, а запасной. Если вы гоняете
переключения скриптом — оставляйте паузы и не устраивайте очередь из смен подряд.

## Проверено

В репозитории лежит автотест из 30 схем, который строит конфигурацию, применяет её и сверяет
фактическое состояние дисплеев с заявленным — включая позиции, частоты, повороты, состав групп
дублирования и HDR. Последний прогон на связке «два монитора + телевизор»: **30 из 30**. Сам отчёт остаётся
на машине, где шёл прогон, — `tests\selftest-log.txt`; в репозиторий он не кладётся.

Что покрыто: каждый экран по отдельности; все пары врастяжку и все пары дублированием; тройка
врастяжку, дубль пары с третьим сбоку во всех сочетаниях, все три в дубль; вертикальный стек,
уголок, экран слева от основного (отрицательные координаты), основной в середине; пониженное
разрешение, смешанные частоты, поворот 90° и 270°; каждый экран в роли основного; включение
и выключение HDR, HDR на трёх экранах сразу и отказ HDR в дубле; повторное применение того же
профиля и профиль, ссылающийся на неподключённый монитор.

Панель задач проверялась иначе — снятием цвета с экрана: каждый вид применялся и замерялся
пиксель самой панели, а каждое состояние воспроизводилось по-настоящему (окно, разворот,
«Пуск», поиск, представление задач) и красилось своим цветом. Шесть состояний из семи сошлись;
седьмое, экономию заряда, на настольной машине воспроизвести нечем — там нет батареи.

## Если что-то пошло не так

- Раскладка не применилась — в строке состояния будет причина. Чаще всего монитор из профиля
  физически выключен: по HDMI выключенный телевизор просто исчезает из системы.
- Экран погас после эксперимента — `Win+P` вернёт картинку, дальше можно применить рабочий профиль.
- Сочетание не срабатывает — `DIIISPL.exe /list` покажет назначенные, а конфликт с чужой
  программой виден по всплывающему предупреждению при запуске.
- Панель задач не меняется — менять её умеют только сборки Dev. Если у вас такая,
  проверьте, лежит ли `DIIISPL.ExplorerTAP.dll` рядом с программой,
  и посмотрите `DIIISPL.exe /taskbar-state`: там видно, сколько панелей найдено, что программа
  считает происходящим на экранах и какое состояние из этого следует. Если рядом работает
  TranslucentTB, оформление задают обе программы наперегонки — оставьте одну.

## Как устроен репозиторий

Публичное и приватное разведены по двум репозиториям, а не по веткам и не по совести:

- **этот** — код, сборка, установщик, документация. Всё, что нужно, чтобы собрать
  программу заново;
- **`.backstage`** — подмодуль с приватным: настройки Клода, черновики, заметки,
  словом, то, что относится к работе над программой, а не к ней самой.

Приватные файлы приходят в рабочее дерево ссылками из `.backstage`, а сами ссылки
перечислены в `.gitignore`. Так один и тот же файл не лежит в двух местах и не
расходится сам с собой, а в открытый репозиторий не попадает ничего лишнего —
даже случайно, потому что git его там попросту не видит. Ссылки расставляет
`Scripts\link-backstage.cmd`: настоящие символьные ссылки на Windows требуют
особых прав, поэтому папки связываются соединением, а файлы — жёсткой ссылкой.

У постороннего приватная часть не выкачивается: `git clone` даёт полностью рабочее
дерево без неё. Сертификат подписи не лежит ни в одном из репозиториев — только
на машине владельца ключа и в секретах сборщика.

Подмодуль даёт то, чего не даёт папка рядом: каждый коммит записывает, **какая
версия приватной части к нему относится**. Откат кода на месяц назад вернёт и ту
документацию, которая его описывала. Платой за это адрес приватного репозитория
попадает в открытое дерево — и это приемлемо, потому что **адрес не есть доступ**:
URL говорит, где репозиторий, а GitHub отвечает отказом всякому, у кого нет прав.

## Сборка

Локально, без сборщика:

```
build.cmd
```

Требуется только компилятор C# из .NET Framework, который есть в Windows 11 по умолчанию.
Ничего скачивать и устанавливать не нужно.

Без аргументов собирается стабильный канал. Сборка Dev — со своими настройками панели
задач и командами `/taskbar` — собирается так:

```
build.cmd dev
```

Библиотека оформления панели задач собирается отдельно. В репозитории её нет — двоичные
файлы туда не кладутся, — так что после клонирования соберите её один раз (или возьмите
готовую из релиза); в дальнейшей работе пересобирать её незачем:

```
native\build-native.cmd
```

Вот для неё нужны Visual Studio Build Tools с рабочей нагрузкой «Разработка на C++»
и Windows SDK; остальное — пакеты NuGet и зависимости vcpkg (detours, wil) — скрипт
подтягивает сам. Промежуточные файлы он складывает в `%TEMP%\diiispl-native`: заголовки
C++/WinRT легко перешагивают ограничение пути в 260 символов, если собирать на месте.

Значок программы лежит в репозитории готовым (`DIIISPL.ico`, девять размеров от 16 до 256),
но не нарисован в редакторе, а собирается кодом — так его можно поправить, не заводя
графический редактор и не гадая, чем он был сделан.

Крупные размеры сделаны в подаче Fluent: слои с мягкой тенью, диагональный градиент,
кромка света по верхнему краю и приглушённый блик — свет один на весь знак и падает
сверху слева. Мелкие рисуются иначе, плоским силуэтом: в 16 точках тень и блик
превращаются в грязь. Так же поступает и сама Windows — под мелкие размеры у её
значков отдельная отрисовка, а не уменьшенная крупная.

```
tools\make-icon.cmd
```

Скрипту можно передать путь к PNG — тогда он ещё и сложит лист со всеми размерами
на светлом и тёмном фоне, включая мелкие крупным планом.

Автотест — отдельно:

```
tests\run-tests.cmd
```

Он по-настоящему переключает мониторы около сорока раз, занимает примерно пять минут
и пишет отчёт в `tests\selftest-log.txt`. Перед началом спросит согласия — надо напечатать
«да» или сразу передать `--yes`. Схемы рассчитаны на три конкретных монитора автора: без
них прогон откажется начинаться. Отдельные проверки — по номерам: `run-tests.cmd 21 26`.

Исходники: `Native.cs` (WinAPI), `Edid.cs` (разбор EDID), `Monitors.cs` (опознание мониторов
и режимы), `Layout.cs` (профиль), `Applier.cs` (сборка конфигурации и HDR), `Store.cs` (файлы),
`Hotkey.cs` (сочетания), `Theme.cs` + `Fluent.cs` (оформление), `MonitorCanvas.cs` (холст),
`MainWindow.cs` (окно), `ConfirmDialog.cs` (вопросы), `App.cs` (трей, горячие клавиши,
автозапуск), `Cli.cs` (командная строка).

Панель задач: `TaskbarSettings.cs` (состояния и виды в профиле), `TaskbarWatcher.cs` (что
происходит на экранах и какой вид из этого следует), `TaskbarWindow.cs` (экран настроек),
`ExplorerTap.cs` (вызовы к службе оформления), `native/` (сама библиотека — C++).

Общее для окон: `Ui.cs` — карточки, строки настроек и заголовки, из которых сложены
экраны, чтобы они выглядели одинаково не по совпадению; `AboutWindow.cs` — «О программе».

Значок: `tools/MakeIcon.cs` — рисование и запись `.ico`. Готовый `DIIISPL.ico` лежит
в программе одной копией — ресурсом Win32; его показывают проводник, панель задач
и Alt+Tab, оттуда же берётся значок для трея, с указанием нужного размера.

## Выпуск

Выпуск собирает GitHub Actions по тегу — версию берёт оттуда же:

```
git push && git tag v0.1.1 && git push --tags
```

Сборщик собирает программу и установщик — а для канала Dev ещё и библиотеку
оформления, — подписывает их, если в секретах репозитория лежит сертификат
(`SIGN_PFX` — PFX в base64, `SIGN_PFX_PASSWORD` — пароль к нему), и прикладывает
пакет к выпуску.

Тег задаёт не только версию, но и канал. Без суффикса — стабильная сборка;
с суффиксом (`v0.1.1-dev.1`) — сборка Dev: она уезжает предварительным выпуском,
и только в ней есть настройки панели задач.
